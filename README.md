# Transportation Overlay

Маленькое Windows-приложение, чтобы не пропустить момент выхода с работы на транспорт.

Оно живет в трее, вечером проверяет live-прогноз Яндекс Карт для нужной остановки и показывает компактный оверлей в углу экрана. Смысл не в полноценном расписании, а в короткой подсказке: выходить сейчас или можно еще спокойно досидеть.

![Оверлей с ближайшими автобусами](docs/overlay-preview.svg)

В трее дополнительно видно число минут до ближайшего автобуса:

![Иконка в трее](docs/tray-preview.svg)

## Что умеет

- показывает выбранные маршруты и ближайшие прибытия в минутах;
- обновляет данные по таймеру;
- работает только в заданный вечерний период, если включено расписание;
- добавляет себя в автозапуск при первом запуске и позволяет отключить это из трея;
- показывает подробности в tooltip трея;
- справа показывает среднюю оценку пробок и три цветные точки Яндекса;
- не превращает частотные интервалы Яндекса вроде "каждые 8 минут" в фейковые прибытия.

## Запуск

```powershell
uv sync
uv run python main.py
```

## Ярлык для панели задач

Чтобы запускать пилот из исходников без сборки exe, можно поставить обычный Windows-ярлык на PowerShell-скрипт:

```powershell
.\scripts\install-shortcut.ps1
```

Скрипт создаст ярлык `Transportation Overlay` в меню «Пуск». Его можно закрепить на панели задач. Сам ярлык запускает `scripts\launch-hidden.vbs`, тот скрыто вызывает `scripts\launch.ps1`, а `launch.ps1` уже стартует `main.py` из текущей папки проекта. Ярлык использует иконку `assets\transportation-overlay.ico`; исходники лежат в `assets\transportation-overlay.svg` и `assets\transportation-overlay-generated.png`. Если приложение уже запущено, повторный запуск перезапустит его: старый процесс завершится, новый останется единственным.

Если ярлык на рабочем столе тоже нужен:

```powershell
.\scripts\install-shortcut.ps1 -Desktop
```

Логи запуска лежат в `%APPDATA%\TransportationOverlay\logs`.

## Сборка exe

Для локальной сборки Windows-исполняемого файла нужен Python 3.11+.

```powershell
.\build.ps1
```

Скрипт установит зависимости проекта и `PyInstaller`, затем соберет приложение в:

```text
dist\TransportationOverlay.exe
```

Если нужен вариант папкой, а не одним большим exe:

```powershell
.\build.ps1 -OneDir
```

После сборки рядом с exe можно положить свой `config.toml`. При запуске приложение сначала ищет конфиг в текущей папке, затем рядом с exe. Если внешний конфиг не найден, используется `config.toml`, упакованный в сборку.

## Настройка

Основное лежит в `config.toml`:

```toml
[app]
title = "Транспорт домой"

[schedule]
enabled = true
active_from = "18:30"
active_to = "21:00"
poll_seconds = 30
inactive_check_seconds = 300

[yandex]
stop_ids = ["1543190229", "stop__1543190229"]
routes = ["23", "28"]
arrivals_per_route = 3
```

`enabled = true` включает автоматические триггеры: в `active_from` отслеживание включается, в `active_to` выключается. Между этими триггерами состояние можно менять вручную.

`poll_seconds` лучше не делать слишком маленьким: частые запросы могут привести к ограничениям или капче со стороны Яндекса.

## Управление

- одиночный клик по иконке в трее переключает отслеживание в любом состоянии;
- правый клик открывает меню с переключателем отслеживания, автозапуском и выходом;
- tooltip трея показывает все маршруты и время последнего обновления.

## Автозапуск

При первом запуске приложение включает автозапуск для текущего пользователя через реестр Windows `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.

Если приложение запущено из собранного exe, в автозапуск попадает путь к exe. Если оно запущено из исходников, сохраняется команда запуска текущим Python из корня проекта.

Отключить или снова включить автозапуск можно через пункт `Автозапуск` в меню иконки в трее. Выбор сохраняется в `%APPDATA%\TransportationOverlay\settings.json`.

## Данные

Приложение использует live-события прибытия из ответа Яндекса (`Estimated` / `Scheduled`). Если реальных событий для маршрута нет, приложение показывает отсутствие данных, а не красиво выглядящие, но сомнительные числа.

### Пробки

Справа от времени автобусов расположен средний балл и вертикальная колонка из трёх точек. Порядок сверху вниз: Паруйра Севака, Рубинянц, Рубинянц — развязка. Координаты и интервал обновления задаются в `[traffic]` и трёх `[[traffic.points]]` в `config.toml`. По умолчанию обновление раз в 120 секунд, только при включённом отслеживании. `enabled = false` скрывает блок.

Цвет определяется по ближайшей цветной линии слоя Яндекс Пробок в радиусе примерно 27 метров от координаты. На дорогах с двумя направлениями выбирается ближайшая линия; на развязке это не оценка всех съездов. Используется проекция Яндекса WGS84 Mercator и соседние тайлы, если точка находится у края изображения.

Средний балл — **наша приблизительная оценка**, не официальный городской балл Яндекса: зелёный = 1, жёлтый = 4, оранжевый = 7, красный = 9, бордовый = 10. Среднее показывается с одним десятичным знаком только при наличии всех трёх точек. При отсутствии линии или ошибке загрузки точка серая, средний балл — прочерк. Наведение показывает названия, оценку, время получения и ошибки. Данные пробок запрашиваются независимо от прибытия автобусов.

Используется недокументированный адрес слоя сайта Яндекса; если Яндекс изменит формат или ограничит доступ, источник потребуется обновить. Ключ API не нужен. Обновление тайлов самим Яндексом может задерживаться на несколько минут.
